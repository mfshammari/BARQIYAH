# حساب الأدمن

حساب الأدمن يحتاج مستخدماً في `auth.users`، وكلمة المرور تُشفَّر داخل Supabase —
فلا يمكن إنشاؤه بـ SQL وحده بأمان. الطريق: أنشئ حساباً عادياً، ثم ارفع دوره.

## الطريقة الأولى — من محرّر SQL (لا تحتاج أي مفاتيح)

١. تأكّد أنك طبّقت `supabase/setup.sql` في **SQL Editor** (يشمل الترحيل `0010`).

٢. سجّل حساباً عادياً من صفحة **إنشاء حساب** في الموقع، بالبريد الذي تريده أدمن.
   (إن كان تأكيد البريد مفعّلاً في مشروعك، أكّده أولاً.)

٣. في **SQL Editor** نفّذ:

```sql
select public.grant_admin('your@email.com', 'admin_owner');
```

يرجع صفاً واحداً بالبريد والدور والمعرّف. سجّل الخروج ثم الدخول، وستفتح لك `/admin`.

## الطريقة الثانية — سكربت التهيئة (يحتاج مفتاح الخدمة)

ينشئ ثلاثة حسابات تجريبية دفعةً واحدة: أدمن، صاحب مناسبة، ماسح.

```bash
# في .env.local أو في البيئة
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJ...          # من Supabase → Settings → API
SEED_ADMIN_EMAIL=your@email.com           # اختياري، الافتراضي admin@barqiyah.sa
SEED_PASSWORD='كلمة-مرور-قوية'            # اختياري، الافتراضي Barqiyah#2026

node scripts/seed-users.mjs
```

> مفتاح الخدمة يتجاوز كل سياسات RLS. لا تضعه في متغيّرات `NEXT_PUBLIC_*`
> ولا ترفعه إلى المستودع.

## الأدوار الإدارية

| الدور             | الاسم في اللوحة | ماذا يرى                                    |
|-------------------|-----------------|---------------------------------------------|
| `admin_owner`     | مدير            | كل شيء، ومنه إدارة الفريق والصلاحيات        |
| `admin_support`   | دعم             | التشغيل اليومي والعملاء والتذاكر            |
| `admin_reviewer`  | مراجع           | مراجعة القوالب واعتمادها                    |
| `admin_finance`   | محاسب           | المالية والفواتير — بلا مراقبة واتساب        |

قائمة الشريط الجانبي تُبنى من صلاحيات كل عضو، فالمحاسب لا يرى «مراقبة واتساب» أصلاً.

بعد أول أدمن، تُدار بقية الترقيات من **لوحة الإدارة ← الفريق والصلاحيات**
دون العودة إلى SQL.

## ملاحظة أمنية

`handle_new_user` كان يقرأ الدور من بيانات التسجيل التي يرسلها العميل، فكان
بإمكان أي شخص يملك المفتاح العام أن يسجّل نفسه `admin_owner`. الترحيل `0010`
يسدّ ذلك: كل حساب جديد يُنشأ بدور `user` مهما أُرسل، ورفع الدور يمرّ عبر
`grant_admin` التي ترفض أي مستدعٍ مسجَّل الدخول لا يملك صلاحية إدارة الفريق.

الاختبارات في `supabase/tests/admin_role.test.sql` تثبت السلوكين.
